# Статика vs Динамика (Static vs Dynamic)

Два фундаментальных подхода к построению торговой системы. Не взаимоисключающие: при грамотной структуре **сочетаются**.

---

## Статика (Static)

**Статика** — торговая система с заранее определёнными, неизменными правилами. При наличии всех условий → позиция открывается. При их отсутствии → позиция не открывается.

Аналогия: бросок монеты с фиксированной ставкой и заранее выбранным правилом — правила неизменны, результат определяется вероятностью и дисциплиной.

### Плюсы статики
- Чёткие протестированные правила — торговля близка к роботизированной
- Бэктест прозрачен: есть точные данные о работе параметров во времени
- Надёжность на дистанции за счёт доверия математике и вероятности

### Минусы статики
- Крайне сложно изобрести оптимальный набор инструментов — требуются опыт, знания, ментор
- Нет гибкости: иногда приходится брать трейд «по правилу», даже если интуиция против

---

## Динамика (Dynamic)

**Динамика** — гибкий подход, где решения принимаются исходя из **уникальности каждой рыночной ситуации**. Параметры подстраиваются под текущий момент.

### Плюсы динамики
- Проста в понимании: видеть события и реагировать на них — интуитивно
- Полная свобода действий и самовыражения, нет жёстких ограничений

### Минусы динамики
- На практике крайне сложна: требует **тысячи часов бэктеста и реальной торговли** для выработки интуитивного восприятия
- Трудно тестировать: каждая ситуация уникальна → невозможно создать надёжную статистику
- Риск несогласованности: логика бэктеста и торговля «вживую» расходятся

---

## Гибридный подход: Static + Dynamic

Статика и динамика могут работать в **связке через контекст**:

- **Статический контекст** — правило неизменно: например, PDH снят → контекст шортовый; PDL снят → контекст лонговый. Без обсуждений и дополнительных условий.
- **Динамический набор позиции** — выбор модели входа исходя из того, что предоставляет рынок в данный момент: m5m1, m3, m15m1 и т. д.

Пример:
> Я определяю контекст через PDL/PDH. Снятие PDL → лонговый контекст. Это статика. Как именно войти — через m5m1 или m3 BOS — решаю динамически исходя из текущей картины рынка.

### Требования к гибриду

- Подход должен быть **протестирован**
- Внутри сетапа должна быть **чёткая логика**
- Нельзя смешивать произвольно: «статика» контекста должна быть жёсткой, «динамика» входа — ограниченной набором валидных моделей

## Как создать Static Setup

Практическое руководство по построению статической торговой системы. Главный тест: **смог бы бот понять этот алгоритм?** Если правило нельзя описать однозначно — оно не статическое.

### Шаг 1. Инструмент

Каждый инструмент имеет свои характеристики и динамику. То, что работает на EURUSD, необязательно работает на USDJPY. Определи **один основной актив** сразу.

### Шаг 2. Стиль торговли

Swing / Intraday / Long-Term — выбрать заранее. Более высокий временной диапазон → выше процент винрейта (технические аспекты строятся на более высокой ликвидности → выше доверие).

### Шаг 3. Контекстный элемент

Контекст — самый важный фактор. Нужна чёткая опора при выборе стороны работы. Варианты:

**Время** — привязка к конкретному событию/времени:
> «Каждую третью среду месяца, открытие Франкфуртской сессии даёт движение в шорт к первой FTA»

**Точки на графике** — привязка к конкретному действию:
> «После снятия PWL/PWH цена всегда даёт коррекцию минимум 50 пунктов»

**Тренд через технический элемент** — ведение за рукой тренда через конкретный инструмент:
> «1H Fractal Structure как основной ориентир. Направление фрактальной структуры → технические переменные для входа»

### Шаг 4. Переменные набора позиции

Выбрать из возможных вариаций (показывает бэктест):
- `1H3M` модель
- `30M OB`
- `4H FVG`
- `NYM test + LG`

Переменные **не могут меняться** в процессе. Static — это строгость условий. Изменение правил разрушает всю цепочку статистики.

> Статика проста в представлении. Вариаций — миллион. Но прийти к положительной статистике через разработку и тестирование всех переменных — одна из самых сложных задач.
