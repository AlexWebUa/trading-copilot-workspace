# 🏗️ Architecture - Система Аудита Кодовой Базы

## 📋 Обзор

Система аудита состоит из **3 специализированных агентов**, работающих в координации:

```
User (запускает /CodeAuditCoordinator)
    ↓
┌─────────────────────────────────────────┐
│   CodeAuditCoordinator                  │
│   (Главный координатор)                 │
├─────────────────────────────────────────┤
│ • Инициирует анализ                     │
│ • Делегирует подзадачи                  │
│ • Собирает результаты                   │
│ • Предоставляет итоговый отчёт          │
└─────────────────────────────────────────┘
         ↙                          ↘
┌──────────────────────┐      ┌──────────────────────┐
│  CodeAnalyzer        │      │  FindingsLogger      │
│  (Анализатор)        │      │  (Логгер)            │
├──────────────────────┤      ├──────────────────────┤
│ • Исследует проект   │      │ • Структурирует      │
│ • Ищет проблемы      │  ──→ │ • Форматирует        │
│ • Классифицирует     │      │ • Сохраняет логи     │
│ • Предлагает решения │      │ • Обновляет индекс   │
└──────────────────────┘      └──────────────────────┘
                                          ↓
                              ┌──────────────────────┐
                              │   Логи в Markdown    │
                              ├──────────────────────┤
                              │ audit-logs/          │
                              │ • INDEX.md           │
                              │ • audit-log-*.md     │
                              │ • README.md          │
                              └──────────────────────┘
```

## 🔧 Компоненты

### 1. CodeAuditCoordinator (Главный координатор)

**Местоположение**: `~/.vscode/User/prompts/CodeAuditCoordinator.agent.md`

**Роль**: Оркестрирует весь процесс аудита

**Инструменты**: `search`, `read`, `agent`, `web`

**Процесс**:
1. Получает запрос от пользователя
2. Определяет scope анализа
3. Вызывает `CodeAnalyzer` субагентом
4. Передаёт результаты `FindingsLogger` субагентом
5. Возвращает пользователю итоговый отчёт

**Интерфейс**: User-invocable (видно в Command Palette)

```
/CodeAuditCoordinator [путь] [тип: full|quick|focus:module]
```

---

### 2. CodeAnalyzer (Анализатор кода)

**Местоположение**: `~/.vscode/User/prompts/CodeAnalyzer.agent.md`

**Роль**: Глубокий анализ кодовой базы

**Инструменты**: `search`, `read` (только чтение, без изменений)

**Поиск**:
1. **Ошибки в коде** - баги, undefined references, type errors
2. **Нарушения Best Practices** - плохой код, архитектурные проблемы
3. **Возможности Оптимизации** - медленные алгоритмы, кэширование
4. **Возможности Рефакторинга** - DRY, SOLID, дублирование
5. **Проблемы Производительности** - утечки памяти, неэффективные операции

**Выходные данные**: Структурированный список находок с:
- Точным расположением (файл:строка)
- Описанием проблемы
- Предложением решения
- Приоритетом (critical/high/medium/low)

**Вызывается**: CodeAuditCoordinator

**User-invocable**: false (только как субагент)

---

### 3. FindingsLogger (Логгер)

**Местоположение**: `~/.vscode/User/prompts/FindingsLogger.agent.md`

**Роль**: Структурирование и логирование находок

**Инструменты**: `edit`, `read`

**Функции**:
1. Парсит результаты CodeAnalyzer
2. Структурирует по категориям и приоритетам
3. Форматирует в Markdown
4. Создаёт/обновляет файл лога
5. Обновляет INDEX.md

**Выходные данные**: 
- Файл: `trading-copilot/audit-logs/audit-log-YYYY-MM-DD.md`
- Обновлённый: `trading-copilot/audit-logs/INDEX.md`

**Вызывается**: CodeAuditCoordinator

**User-invocable**: false (только как субагент)

## 🔄 Жизненный цикл аудита

```
1. ИНИЦИАЛИЗАЦИЯ
   ↓
   User запускает: /CodeAuditCoordinator [параметры]
   ↓
   CodeAuditCoordinator парсит параметры

2. АНАЛИЗ
   ↓
   CodeAuditCoordinator → CodeAnalyzer (субагент)
   ↓
   CodeAnalyzer исследует кодовую базу:
   • Поиск по файловой системе
   • Анализ кода
   • Классификация проблем
   • Формирование отчёта
   ↓
   Возврат к CodeAuditCoordinator

3. ЛОГИРОВАНИЕ
   ↓
   CodeAuditCoordinator → FindingsLogger (субагент)
   ↓
   FindingsLogger структурирует данные:
   • Парсинг результатов
   • Форматирование Markdown
   • Создание/обновление файла лога
   • Обновление индекса
   ↓
   Возврат к CodeAuditCoordinator

4. ОТЧЁТНОСТЬ
   ↓
   CodeAuditCoordinator компилирует финальный отчёт:
   • Количество проблем
   • Распределение по категориям
   • Ссылка на лог
   • Рекомендации
   ↓
   Вывод для пользователя

5. ЗАВЕРШЕНИЕ
   ↓
   Пользователь получает отчёт
   Может открыть и просмотреть полный лог
   Начать исправление проблем
```

## 🎯 Типы находок и их классификация

### Таблица маршрутизации находок

| Тип | Категория | Приоритет | Пример |
|-----|-----------|-----------|--------|
| Bug | Ошибки в коде | Critical/High | Undefined variable |
| Best Practice | Нарушения | High/Medium | Missing error handling |
| Optimization | Оптимизация | Medium/Low | O(n²) loop → O(n) |
| Refactoring | Рефакторинг | Medium/Low | DRY violation |
| Performance | Производительность | Critical/High | Memory leak |

## 📊 Формат данных

### Вход (User → CodeAuditCoordinator)

```
{
  project_path: "d:\Projects\vibecoding\trading-copilot-workspace",
  analysis_type: "full" | "quick" | "focus:module_name",
  include_security: true,
  include_performance: true,
  output_format: "markdown"
}
```

### Между агентами (CodeAuditCoordinator → CodeAnalyzer)

```
CodeAnalyzer получает:
- Путь к проекту
- Тип анализа
- Направления поиска (5 категорий)

CodeAnalyzer возвращает:
- Список находок с полной информацией
- Классификация по типам
- Приоритеты
```

### Между агентами (CodeAuditCoordinator → FindingsLogger)

```
FindingsLogger получает:
- Результаты анализа
- Метаданные (дата, проект, тип)

FindingsLogger возвращает:
- Путь к сохранённому файлу
- Путь к обновлённому индексу
- Статистика
```

### Выход (CodeAuditCoordinator → User)

```markdown
# 📊 Итоги аудита

**Найдено по категориям:**
- ⚠️ Ошибки: 5
- 🔧 Оптимизация: 8
- 📚 Best Practices: 3
- 🏗️ Рефакторинг: 4
- ⚡ Производительность: 2

**Логи:** trading-copilot/audit-logs/audit-log-2026-04-27.md
```

## 🔐 Безопасность и ограничения

### Ограничения CodeAnalyzer
- ❌ Не может писать в файлы (только читать)
- ❌ Не может удалять файлы
- ❌ Не может запускать команды
- ✅ Только анализ и поиск

### Ограничения FindingsLogger
- ✅ Может писать/редактировать логи
- ❌ Не может писать в исходный код
- ❌ Не может удалять логи (только добавлять)
- ✅ Используется для логирования

### Ограничения CodeAuditCoordinator
- ✅ Может делегировать подзадачи
- ✅ Может читать и искать
- ✅ Может вызывать субагентов
- ❌ Не может напрямую писать код

---

## 📈 Масштабируемость

### Текущая производительность
- **Анализ**: 2-5 минут (в зависимости от размера проекта)
- **Логирование**: 30 сек
- **Суммирование**: 10 сек
- **Всего**: ~3-6 минут на полный аудит

### Оптимизация для больших проектов
- Использовать `quick` анализ вместо `full`
- Использовать `focus:module_name` для конкретных модулей
- Параллелизировать анализ нескольких модулей

## 🔧 Настройка и кастомизация

### Изменение приоритетов

Отредактируйте `CodeAnalyzer.agent.md`:
```markdown
## Ограничения CodeAnalyzer
- Focus на [ваш приоритет 1]
- Затем [приоритет 2]
- ...
```

### Добавление новой категории находок

1. Обновите `CodeAnalyzer.agent.md` (добавьте в поиск)
2. Обновите `FindingsLogger.agent.md` (добавьте в структуру)
3. Обновите пример лога
4. Документируйте в README.md

### Изменение формата логов

Отредактируйте шаблон в `FindingsLogger.agent.md`

## 🐛 Troubleshooting

### Проблема: Агент не находит файлы
**Решение**: Проверьте путь к проекту, используйте абсолютный путь

### Проблема: Находки выглядят неправильно
**Решение**: Проверьте лог, сравните с `EXAMPLE_audit-log-2026-04-27.md`

### Проблема: Логи не сохраняются
**Решение**: Проверьте папку `trading-copilot/audit-logs/`, убедитесь, что она существует

### Проблема: Медленный анализ
**Решение**: Используйте `quick` вместо `full`, или `focus:` для конкретного модуля
