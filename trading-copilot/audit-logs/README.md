# 🔍 Code Audit System - Документация

Система автоматизированного аудита кодовой базы, которая находит ошибки, возможности оптимизации, нарушения best practices и другие технические улучшения.

## 🚀 Быстрый старт

### 1. Запуск аудита

Откройте VS Code и используйте агент `CodeAuditCoordinator`:

```
/CodeAuditCoordinator
```

Затем укажите:
- **Путь к проекту** (или оставьте пусто для текущего проекта)
- **Тип анализа** (по умолчанию `full`):
  - `full` - полный анализ всей кодовой базы
  - `quick` - быстрый анализ (основные проблемы)
  - `focus:module_name` - анализ конкретного модуля

### 2. Результаты

Агент:
1. 🔎 **Исследует** кодовую базу с помощью CodeAnalyzer
2. 📝 **Логирует** все находки через FindingsLogger
3. 📊 **Показывает** итоговый отчёт

Логи сохраняются в: `trading-copilot/audit-logs/`

---

## 📋 Структура логов

Каждый лог содержит находки, разделённые по 5 категориям:

### 1. **Ошибки в коде** (Bugs)
Потенциальные краши, undefined references, type errors, логические ошибки

**Пример**: Переменная используется без инициализации, может привести к NameError

### 2. **Нарушения Best Practices**
Плохие практики, отсутствие error handling, неправильные имена переменных

**Пример**: Отсутствует try-except при работе с БД, приложение может упасть

### 3. **Возможности Оптимизации**
Медленные алгоритмы, отсутствие кэширования, неэффективные операции

**Пример**: Отсутствуют индексы в БД, запросы выполняются медленно

### 4. **Возможности Рефакторинга**
Дублирование кода (DRY violation), большие функции, нарушение SOLID принципов

**Пример**: Одинаковая логика валидации повторяется в 3 файлах

### 5. **Проблемы Производительности**
Утечки памяти, неэффективные циклы, тяжёлые операции

**Пример**: Слушатели событий никогда не удаляются из памяти

...

---

## 🔄 Жизненный цикл находок

Каждая находка проходит следующие статусы:

1. **`not-started`** - Найдена, но ещё не начата
2. **`in-progress`** - Работа над исправлением ведётся
3. **`completed`** - Исправлено и протестировано

**Обновление статуса**: Отредактируйте лог вручную или используйте агент `ImplementationAgent` (в разработке)

## 📂 Структура папки audit-logs

```
audit-logs/
├── INDEX.md                          # Индекс всех логов
├── EXAMPLE_audit-log-2026-04-27.md   # Пример лога с подробностями
└── audit-log-2026-04-27.md          # Реальный лог аудита (при наличии)
```

### INDEX.md
Главный файл с навигацией:
- Список всех логов с датами
- Статистика по проектам
- Ссылки на все логи
- Инструкции по использованию

### audit-log-YYYY-MM-DD.md
Основной лог одного анализа:
- Находки, разделённые по категориям и приоритетам
- Таблица со статистикой
- Рекомендуемый порядок внедрения
- Метаинформация об анализе

## 🎯 Приоритеты

| Приоритет | Описание | Действие |
|-----------|---------|---------|
| **Critical** | Ломает функциональность, может привести к краху | Исправить немедленно |
| **High** | Серьёзные проблемы, могут привести к ошибкам | Исправить в ближайшее время |
| **Medium** | Значительные улучшения, влияют на качество | Запланировать исправление |
| **Low** | Небольшие улучшения, рекомендации | Рассмотреть при наличии времени |

## 🔧 Использование с другими агентами

### CodeAnalyzer (Анализатор)
- Ищет ошибки и проблемы
- Классифицирует по категориям
- Предоставляет рекомендации
- **Используется**: CodeAuditCoordinator вызывает его для анализа

### FindingsLogger (Логгер)
- Преобразует находки в структурированный формат
- Сохраняет в файлы markdown
- Обновляет индекс
- **Используется**: CodeAuditCoordinator отправляет ему результаты

### ImplementationAgent (В разработке)
- Будет читать логи
- Предлагать конкретные исправления
- Помогать внедрять изменения
- Обновлять статусы

## 🆘 Часто задаваемые вопросы

### Q: Почему агент не находит ошибки в моём коде?
**A**: Попробуйте более специфичный тип анализа или укажите точный путь к проекту. Используйте `focus:` для анализа конкретного модуля.

### Q: Как обновить найденные проблемы?
**A**: Отредактируйте лог вручную, измените `Статус` на `in-progress` или `completed`.

### Q: Могу ли я запустить аудит несколько раз в день?
**A**: Да, но каждый новый запуск создаст новый файл лога. Старые логи сохранятся в индексе.

### Q: Как фильтровать находки по приоритету?
**A**: В каждом логе находки разделены по приоритетам. Используйте поиск по "Critical", "High", "Medium", "Low".

### Q: Можно ли анализировать только новый код?
**A**: Используйте `focus:module_name` для анализа конкретного модуля.
