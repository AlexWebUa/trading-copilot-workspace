## Найденные проблемы

### Ошибки в коде (High)

1. **Проблема**: Миграции БД полностью подавляют ошибки (silent fail)
- **Файл**: copilot/journal/db.py:88
- **Тип**: error
- **Описание**: В блоке миграции используется пустой `except: pass`, из‑за чего ошибки миграции скрываются.
- **Решение**: Логировать исключение с traceback и/или пробрасывать ошибку; убрать пустой `except` и обеспечить откат/уведомление при неудачной миграции.
- **Статус**: not-started

2. **Проблема**: Использование `assert` для критичных инвариантов в рантайме
- **Файл**: copilot/backtest/engine.py:287
- **Тип**: error
- **Описание**: `assert` используется для проверки инвариантов; при запуске с `-O` эти проверки отключаются.
- **Решение**: Заменить `assert` на явные проверки и бросать конкретные исключения (например, `RuntimeError`) с информативным сообщением.
- **Статус**: not-started

## Нарушения Best Practices (Medium)

3. **Проблема**: Широкий `except Exception:` при вызове детекторов — исключения скрываются
- **Файл**: copilot/backtest/rules.py:412
- **Категория**: error-handling
- **Описание**: Исключения внутри детекторов подавляются без логирования, что превращает ошибки в `False`-результаты.
- **Решение**: Логировать исключение и контекст (имя детектора, аргументы, traceback). В debug — пробрасывать, в проде — возвращать структурированную ошибку.

4. **Проблема**: `ToolRegistry.dispatch` возвращает общий `{"error": ...}` без трассировки
- **Файл**: copilot/llm/tools.py:99
- **Категория**: error-handling
- **Описание**: Общий возврат ошибки без трассировки затрудняет диагностику проблем инструментов.
- **Решение**: Перехватывать конкретные исключения, логировать traceback; при необходимости добавлять в ответ краткое debug-поле.

5. **Проблема**: Предзагрузка HTF/LTF данных в `BacktestEngine` подавляет ошибки при fetch
- **Файл**: copilot/backtest/engine.py:240
- **Категория**: reliability
- **Описание**: Ошибки при загрузке высоко/низко таймфреймовых данных игнорируются, теряется причина недоступности данных.
- **Решение**: Логировать причину fetch-ошибки; выставлять мета-флаг/статус при недоступности данных.

6. **Проблема**: В `_fetch_shared_df` при падении delta-fetch используется `pass` — причина игнорируется
- **Файл**: copilot/backtest/compare.py:111
- **Категория**: reliability
- **Описание**: При падении попытки получить delta данные причина замалчивается, применяется fallback без логирования.
- **Решение**: Логировать исключение; при fallback фиксировать причину (timeout/HTTP/JSON).

7. **Проблема**: Широкие `except Exception as e` в CLI/backtest/report без логирования стеков
- **Файл**: copilot/cli.py:355
- **Категория**: error-handling
- **Описание**: Пользователь получает сообщение об ошибке, но стек не сохраняется, усложняя отладку.
- **Решение**: Показывать краткую ошибку пользователю, а полный traceback логировать (`logger.exception`).

## Возможности оптимизации / Потенциальные проблемы (Low/Medium)

8. **Проблема**: Потенциальное несоответствие API Anthropic
- **Файл**: copilot/llm/agent.py:52
- **Приоритет**: low (potential)
- **Описание**: Вызовы клиента Anthropic могут не соответствовать установленной версией SDK.
- **Решение**: Проверить версию SDK, обернуть вызовы в try/except и добавить интеграционный тест.

9. **Проблема**: `generate_pine_script` использует `ThreadPoolExecutor` и вызывает `.result()` без timeout
- **Файл**: copilot/detectors/pine_script.py:1
- **Приоритет**: medium
- **Описание**: Если задача зависнет, генерация может блокироваться навсегда.
- **Решение**: Использовать `future.result(timeout=...)`, обрабатывать TimeoutError и деградировать результат с логированием.

10. **Проблема**: Десериализация JSON в `_row_to_record` молчит при ошибке и возвращает пустой список
- **Файл**: copilot/journal/db.py:108
- **Приоритет**: medium
- **Описание**: При повреждённых данных десериализация скрывает проблему, возвращая пустые структуры.
- **Решение**: Логировать `JSONDecodeError`/`TypeError` с id записи; при повторяющихся ошибках — сигнализировать о повреждённых строках в БД.

11. **Проблема**: В `copilot/` и `tests/` не найдено `eval`/`exec`/`pickle.loads` с внешними данными (информационно)
- **Приоритет**: low
- **Описание**: Потенциальные опасные вызовы присутствуют только в `.venv_mcp` (внешние библиотеки).
- **Решение**: Поддерживать изолированное окружение и избегать ненадёжной десериализации из внешних пакетов.

12. **Проблема**: Смешение sync/async `httpx.Client` — риск ошибочного использования в async-контексте
- **Файл**: copilot/data/binance.py:73
- **Приоритет**: low
- **Решение**: Документировать где используется sync vs async; при миграции в async — перейти на `httpx.AsyncClient`.
